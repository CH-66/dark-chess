# V0.4 联网对战架构设计

## 目标

V0.4 不直接把联网逻辑硬塞进现有本地规则层，而是先建立可替换的对战边界：

- 本地 Hot Seat 继续作为默认模式；
- 游戏规则保持纯函数、可测试；
- UI 只依赖 GameSession，不直接依赖网络；
- 联网模式采用服务端权威状态；
- 暗棋真实身份永不通过客户端公共状态下发给对手；
- 为房间、重连、回放和观战预留协议字段。

## 分层

```text
UI
 └─ GameSession
     ├─ LocalSession        -> 直接调用 game.js
     └─ OnlineSession       -> WebSocket / HTTPS
                              |
                              v
                         Game Server
                         ├─ Room
                         ├─ Authoritative GameState
                         ├─ Visibility Filter
                         └─ Replay/Event Store
```

### 1. Rule Engine

`src/game.js` 是唯一规则来源。

服务端未来应复用同一规则语义，而不是让浏览器端自行决定胜负。V0.4 先固定以下领域接口：

- `createGame(seed)`
- `legalTargets(state, piece)`
- `movePiece(state, pieceId, x, y)`
- `revealInPlace(state, pieceId)`

### 2. Session

建议抽象：

```js
class GameSession {
  getView()
  select(pieceId)
  move(pieceId, x, y)
  reveal(pieceId)
  restart()
  subscribe(listener)
  dispose()
}
```

`LocalSession` 直接包裹当前状态；`OnlineSession` 只负责发送命令、接收服务端事件和更新公开视图。

### 3. 服务端权威

客户端提交意图，而不是提交结果：

```json
{
  "type": "game.command",
  "roomId": "room-123",
  "commandId": "cmd-42",
  "expectedRevision": 17,
  "command": {
    "type": "move",
    "pieceId": "RED-0-9",
    "to": {"x": 0, "y": 7}
  }
}
```

服务端校验：

1. 房间存在；
2. 玩家身份与阵营匹配；
3. revision 未过期；
4. 当前确实轮到该玩家；
5. 目标移动符合规则；
6. 暗棋首次行动只能按 originalType；
7. 翻棋/移动后的真实身份只在允许范围内进入玩家视图；
8. 产生新 revision 后广播事件。

## 可见性模型

服务端内部保存：

- `actualType`
- `originalType`
- `side`
- `position`
- `alive`
- `revealed`

玩家视图只允许收到：

- 自己已经知道的真实身份；
- 对手已经公开的真实身份；
- 棋子颜色/阵营、位置、存活状态；
- 当前回合；
- 合法的公开事件。

禁止公共消息携带完整服务端 GameState。

## 事件模型

推荐事件：

- `room.created`
- `player.joined`
- `game.started`
- `game.move.accepted`
- `game.piece.revealed`
- `game.piece.captured`
- `game.finished`
- `game.resync`
- `player.disconnected`
- `player.reconnected`

每个事件携带：

```json
{
  "roomId": "room-123",
  "revision": 18,
  "eventId": "evt-18",
  "serverTime": "2026-09-19T03:00:00Z",
  "type": "game.move.accepted",
  "payload": {}
}
```

## 重连

客户端保存：

- `roomId`
- `playerId`
- `sessionToken`
- `lastRevision`

重连后发送：

```json
{
  "type": "game.resync",
  "roomId": "room-123",
  "lastRevision": 18
}
```

服务端：

- revision 连续可补事件时，发送缺失事件；
- 无法补事件时，发送经过 Visibility Filter 的完整当前视图；
- 不重新生成随机棋局。

## 防作弊原则

V0.4 只定义边界，不宣称浏览器端安全。

必须做到：

- seed 不作为服务端真实随机身份的安全来源；
- 对局创建时由服务端生成随机布局；
- 客户端不能指定 actualType；
- 客户端不能提交 captured / winner；
- 服务端不能把隐藏身份放入广播消息；
- 开发者工具看到的只能是该玩家有权知道的数据。

## 传输

首选 WebSocket：

- HTTP：创建房间、加入房间、获取一次性连接凭证；
- WebSocket：实时命令与事件；
- HTTPS：历史对局、回放、房间元数据。

V0.4 不绑定具体框架。Node.js + WebSocket / Socket.IO 均可作为后续实现候选。

## 版本兼容

所有消息建议带 `protocolVersion`：

```json
{
  "protocolVersion": 1,
  "gameVersion": "0.4"
}
```

规则发生不兼容变化时，不允许旧客户端继续提交旧协议命令。
