# V0.4 第三阶段：OnlineSession 正式接入棋盘 UI

## 目标

把第二阶段已经完成的 `OnlineSession` 真正接到玩家可操作的棋盘，而不是只保留测试入口。

本阶段完成：

- 本地双人与联网对战模式切换；
- 创建房间并显示 8 位房间号；
- 另一浏览器输入房间号加入；
- 双方在真实棋盘上选择、翻棋、移动、吃子；
- 服务端权威结果同步到双方 UI；
- 当前阵营、连接状态、等待对手状态；
- 服务端错误在页面提示并写入对局日志；
- 断线后保留房间凭证，并支持“重新连接”；
- 自动重连尝试 5 次，采用递增等待；
- UI 不再直接调用规则函数完成联网落子，联网落子全部经过 `OnlineSession`；
- E2E 使用真实 WebSocket 游戏服务器，而不是静态文件服务器。

## 用户操作闭环

### 创建方

1. 点击“联网对战”。
2. 点击“创建房间”。
3. 页面显示房间号、红方身份和“等待对手”。
4. 将房间号交给另一位玩家。
5. 第二位玩家加入后，双方棋盘自动进入同一局。

### 加入方

1. 点击“联网对战”。
2. 输入房间号。
3. 点击“加入”。
4. 页面显示黑方身份。
5. 对局开始后，只能操作自己的回合和自己的棋子。

## UI 状态

`OnlineSession` 的连接状态统一映射到：

- 未连接
- 连接中
- 已连接 · 等待对手
- 已连接 · 对局中
- 重连中
- 已断开
- 连接异常

网络断开不会清空：

- roomId
- playerId
- sessionToken
- revision
- 当前已经看到的棋局视图

重新连接后服务端返回当前玩家安全视图。

## 联网落子原则

UI 只发送：

- 棋子 ID；
- 目标坐标；
- 期望 revision；
- commandId。

UI 不发送：

- actualType；
- captured；
- winner；
- nextTurn。

服务端完成规则验证并广播经过 Visibility Filter 的结果。

## 测试门槛

第三阶段最低通过标准：

- 本地规则测试全部通过；
- 浏览器本地 E2E 全部通过；
- 两浏览器真实 WebSocket 房间创建/加入通过；
- 双方真实 DOM 点击完成翻棋和移动；
- 对手隐藏棋子的 actualType 不进入客户端；
- 断线 UI 有明确提示；
- 重新连接后房间号、阵营、revision 和棋盘状态保持；
- GitHub Actions 运行通过。

## 下一阶段：部署与公网联调

下一阶段不继续扩展玩法，而是把当前可运行服务部署到可从公网访问的环境：

- `HOST=0.0.0.0`；
- HTTP + WebSocket 对外监听；
- HTTPS/WSS；
- 反向代理与 WebSocket Upgrade；
- 健康检查；
- 运行日志；
- 最小房间生命周期清理；
- 真机/异地浏览器联调；
- 公网断线/重连验证。

当前阶段不引入登录、匹配、排位、AI 和数据库持久化。
